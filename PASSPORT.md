## 2. Classification

| Field | Value |
|---|---|
| Class | Kubernetes controller / operator, plus per-node exporters, one serverless function and one webhook-receiver Deployment |
| Type | Kubernetes controller (controller-runtime, operator pattern); `gcpevents` = event-bridge function; `promevents` = Alertmanager-webhook event bridge (HTTP service). No agent framework, no MCP server, no prompt templates |
| Custom resource | None — the agent has no Application custom resource; applications are virtual apps derived from workload labels and annotations |
| Run modes | `--mode` is a repeatable flag naming one role per occurrence. Omitted = `controller` (push mode plus optional collectors). Other roles: `ebpf`, `node-exporter`, `log-exporter`, `otlp` (OTLP sensor role, see OTLP sensor role; runs alone) and `host` (Linux host runtime, see Host mode). Several roles in one process run as goroutines, the DaemonSet's combined-role form. `--kubernetes=false` (chart `kubernetes.watch: false`) runs the controller with no Kubernetes watch (see No-Kubernetes mode) |
| Host mode | `--mode=host` runs the agent as a systemd service on a Linux host with no Kubernetes inputs: systemd units (enabled services minus a built-in denylist, or `--host-units` globs) become virtual apps in one synthetic namespace (`--host-namespace`, default `host`); `--target-tenant` is required; the cluster name is `--cluster-name` or the short OS host name. In-process roles: USE from unit cgroups under `--cgroup-root` (cgroup v2), LOG from `journalctl --follow --output=json` per selected unit plus optional plain files named by `--host-log-files` (`<unit>=<glob>`), RED and topology from the embedded OBI instrumenter over unit cgroups (builds with `-tags obi`). Authentication is the join certificate only (`--join-ca-fingerprint` is required with `--triage-endpoint`); join state is kept under `--join-state-dir` (default `/var/lib/triage-agent/join`) |
| OTLP receiver | Controller option (`--otlp-listen`, chart `otlp.enabled`, default off; needs `--sensor-listen`): OTLP/gRPC metrics receiver on the sensor stream's certificate, TLS 1.3 only. The process exits, and the chart refuses to render, when it is enabled with no sender credential source. Credentials: a client certificate chaining to `--otlp-client-ca-file` (chart `otlp.clientCASecret`) and/or to the agent's own client CA (`--otlp-client-ca-secret`, chart `otlp.ownCA`: an ECDSA P-256 CA with 5-year validity, created in a Secret on first use and renewed inside 90 days of expiry, the replaced CA kept in `ca.prev.crt` while it is valid); or a projected ServiceAccount token of audience `triage-agent-otlp` from a `--otlp-allowed-service-accounts` entry (`namespace/serviceaccount` or `namespace/*`), checked by TokenReview with outcomes cached by token hash (accepted 5 minutes, refused 30 seconds, 10000 entries). With a client CA and no token allow-list a client certificate is mandatory (`RequireAndVerifyClientCert`); with both, a certificate is optional and one that is presented must chain to the CA (`VerifyClientCertIfGiven`). Sender identity: a certificate with URI SANs `spiffe://<domain>/tenant/<name>` (name matching `^[a-z0-9]([a-z0-9._-]{0,61}[a-z0-9])?$`) is a tenant sender; a certificate with a `spiffe://<domain>/ns/<namespace>/sa/<name>` URI SAN is that namespace and account; any other certificate is a forwarder named by its common name; a token is the ServiceAccount's namespace and name, or a forwarder when listed in `--otlp-forwarders`. The SPIFFE trust domain is not compared. A forwarder may publish for any namespace. A non-forwarder's resource or point naming another `k8s.namespace.name` is refused or dropped, and a missing resource-level namespace is filled in with the sender's. A tenant sender's resource is placed in one tenant (its `triage.tenant` attribute, or the certificate's only tenant), which must be named by the certificate and be one of the agent's join tenants (`--join-tenant` values plus `--target-tenant`); every namespace on the resource and on its points is rewritten to `<tenant>~<namespace>` and the tenant attribute is removed; a resource whose `k8s.namespace.name` is outside that tenant's workspace namespace scope is refused, and a point naming an out-of-scope namespace is dropped, both counted as refused points with the reason `namespace outside the workspace scope`. Delta sums and delta histograms are added into the resource's cumulative state (an interval ending no later than the last one added is skipped); exponential histograms are refused per point. Traces and logs are accepted as well (see OTLP traces and logs). A metric no collector reads is dropped at intake before its resource takes a quota slot (`ReadByCollectors`; counted as `unread`). A client certificate whose `spiffe://<domain>/tenant/…` URI SAN is malformed is refused; a resource naming more than one `k8s.namespace.name`, or a namespace containing `~`, is refused. Limits, all flags (chart `otlp.limits`): `--otlp-max-resources` 2000, `--otlp-max-points-per-resource` 5000, `--otlp-max-resources-per-sender` 500, `--otlp-max-request-bytes` 4MiB; 10 minutes of silence expires a resource; refusals are counted per sender (at most 1000 sender keys). Metrics are routed by name to the RED, USE or LOG roles; the collectors read namespace and service from the merged resource and data-point attributes, a data point's value winning over the resource's |
| OTLP traces and logs | The same receiver serves the OTLP traces and logs services on its port, behind the same authentication and the same admission checks as metrics. Server and consumer spans become the RED duration histograms and client and producer spans the client histograms (split by span name, kind, status code and the HTTP, RPC and server-address attributes; sixteen explicit bounds from 2ms to 15s); internal spans are ignored. Log records become cumulative `log.errors`, `log.warns` and `log.lines` counters per resource from `severity_number` (severity text when the number is unset). Derived resources carry the attribute `triage.otlp.replica` naming the receiving process, so several receivers' shares of one service stay separate sources that the collectors sum; a source the sender reports natively takes precedence over a derived one for the same (service, metric). No span or log body is stored. Derived series count against `--otlp-max-points-per-resource` |
| OTLP sensor role | `--mode=otlp` (chart `otlp.sensor.enabled`, default off; requires `otlp.enabled`) runs the receiver in its own Deployment `<fullname>-otlp` (2 replicas by default, ClusterIP Service `<fullname>-otlp` on the OTLP port) instead of in the controller; the controller then opens no OTLP listener. The role runs alone. Each pod serves the controller's sensor-stream certificate (mounted from the `<fullname>-sensor-tls` Secret, key included; the chart adds the Service's names to the certificate) and streams every source to the controller over the sensor stream as OTLP snapshots naming their source (`Snapshot.source`), one per (source, data role), every `otlp.sensor.tick` (default 10s), with a full replay after a reconnect and 15 minutes of retention for a silent source. Pods are keyed by pod name. The role authenticates to the controller with the serving certificate as its TLS client certificate instead of a token (§4); the pod mounts no ServiceAccount token unless `otlp.allowedServiceAccounts` is set. The controller (`--sensor-otlp-role`, set by the chart) applies the joined-tenant and workspace-scope checks to every source again (`otlpreceiver.ScopeFilter`). Sender authentication is as for the controller's receiver (client certificate, own CA, ServiceAccount token) or the mode below |
| OTLP unauthenticated mode | Chart `otlp.insecure.enabled` (default off), `--otlp-insecure` in the role: plain gRPC, no sender check, every sender an anonymous forwarder named `anonymous@<remote address>` (quotas and refusal counters per address). The chart renders it only with `otlp.sensor.enabled` and a non-empty `otlp.insecure.allowFrom`, refuses it together with `otlp.ownCA`, `otlp.clientCASecret`, `otlp.allowedServiceAccounts` and `otlp.forwarders`, requires exactly one tenant (`target.tenant`, or one `core.tenants` entry), omits the tenant flags, and renders a NetworkPolicy admitting only the listed namespaces (by `kubernetes.io/metadata.name`) to the OTLP port. The binary itself does not check for the policy; the controller's own receiver has no such mode |
| Held-back entries | Before a collector frame (log, RED, USE, topology) is queued, entries the core would refuse the whole frame over are dropped by name: a service with no namespace or no name, a topology node with either missing, an edge whose source or destination lacks a namespace or workload and has no external host. They are counted (`malformedDropped` in the stats, `Link.MalformedDropped`) and kept as named records in a ledger (at most 64 records, least recently dropped replaced; shown in the local TUI and returned by the local stats route, and published to replicas with the TUI snapshot). A frame left with no entries is not sent, except a topology snapshot |
| Workspace scope persistence | The workspace namespace scope is also written to the join store as `scope.json` (JSON map of tenant to namespaces) on each change and restored after the identity is accepted, so the first snapshots of a new process obey it. A restored scope stands until a `limits` frame replaces it or 30 seconds after a session opened without one, when it is lifted; a join result's bindings are saved when a new identity is issued |
| Replica gossip | With more than one controller replica (`replicaCount` > 1, leader election always on) each replica forwards the sensor and OTLP snapshots it receives to every peer over a WebSocket on `--mesh-listen` (chart `sensorStream.meshPort`, 9471), peers discovered through the headless Service `<fullname>-peers`. Mutual TLS 1.3 in which both sides present and accept exactly the sensor stream's certificate; inbound frame limit 48MiB |
| Tenancy modes | Single-tenant / primary (`--target-tenant` set: that tenant is declared in the hello and is the default for in-scope namespaces carrying no `triageagent.dev/tenant` annotation) and cluster mode (`--target-tenant` empty: no session tenant, every frame carries a tenant derived solely from its namespace's `triageagent.dev/tenant` annotation, and an in-scope namespace with no annotation has its items dropped). A namespace of the form `<tenant>~<namespace>` is routed to that tenant in either mode (remote OTLP tenants); a Kubernetes namespace name cannot contain `~` |
| Remote OTLP tenants | A tenant sender's data reaches the core under the tenant its certificate names, without any namespace of this cluster carrying that tenant's annotation. The first data of a tenant, and the first after 15 minutes of silence, sends that tenant's snapshot sequence on the live connection; a tenant with data inside the 15-minute window is included in the snapshot replay on every reconnect. The `<tenant>~` prefix is removed from every namespace in the frames, the topology edges and the `sensor_state` OTLP list before they leave the agent |
| Client certificate issuing | `triage-agent otlp-cert --tenant a,b --cn <name> --client-ca-secret <secret>` (run in the controller pod with its ServiceAccount): reads the agent's client CA from the Secret, issues an ECDSA P-256 client certificate (extended key usage `clientAuth`, one `spiffe://<domain>/tenant/<tenant>` URI SAN per tenant, default trust domain `triage-agent`, default validity 365 days, never past the CA's expiry), and prints a Secret manifest or PEM blocks, with the agent's serving certificate when `--serving-ca-configmap` is given |
| Workspace namespace scope | The core's `limits` frame carries `namespaces`, a map of tenant to the namespaces the core takes from this agent for that tenant; each frame replaces the whole map. A tenant that is absent, or has an empty list, takes every namespace; so does a source with no namespace. A key-join result's `bindings` seed the map until a limits frame has been received. The map is held in memory only. Until the first limits frame or key-join result of a process every namespace is in scope. Applied at: the OTLP receiver (tenant senders, resource and point level), tenant resolution of every payload item (log, RED and USE services and summaries, topology nodes and the edge's source namespace, app deltas, Kubernetes events), snapshot app filtering and the Kubernetes event informer. Items dropped are counted (`triage_agent_frames_out_of_scope_dropped_total`, `outOfScopeDropped` in the API and TUI) and logged for the first and every thousandth. Not filtered by it: the `sensor_state` frame's OTLP source list, and the destination namespace and workload of a topology edge |
| Event caps | The core's `limits` frame also carries `eventsPerDay`, a cap per tenant (0 = uncapped). The agent holds Kubernetes events to it with one token bucket per tenant that refills evenly over 24 hours and holds one hour's share; events past it are not sent and are counted per tenant |
| No-Kubernetes mode | `--kubernetes=false` (chart `kubernetes.watch: false`) needs a core endpoint and exactly one tenant (`core.tenants` with one entry, or `target.tenant`). No Namespace, Service, Ingress, workload or Event informer runs, no owner reads are made, and the chart renders no controller ClusterRole or ClusterRoleBinding. The Kubernetes client is still used for the join Secret, the sensor-stream serving Secret and ConfigMap, the client CA Secret and TokenReview. Applications come from OTLP workload metrics of a Collector's `k8s_cluster` receiver (Deployment, StatefulSet, DaemonSet; ready when ready counts reach desired counts), else one application per (namespace, service) an OTLP sender reports; everything in scope files under the one tenant. A remote tenant's client-span destination is resolved by host name alone (bare Service name, or `<svc>.<ns>.svc[.<domain>]`); any other destination is `External` |
| Push namespace scope | `--target-namespaces` (repeatable) and the `triageagent.dev/tenant`-annotated set together decide which namespaces are observed and pushed off-cluster; the two union. An empty `--target-namespaces` list means the annotated set only, in both tenancy modes, never every namespace. `--target-tenant` decides tenant attribution for an in-scope namespace, never scope itself. An agent with neither a list nor any annotation observes and pushes nothing. When a namespace's only dynamic (annotation) membership ends, its scope is re-evaluated against the static list alone |
| Manager cache scope (cluster mode) | With `--namespace` unset, `--triage-endpoint` set and `--target-tenant` empty, the informer cache is scoped at startup to the `triageagent.dev/tenant`-annotated namespaces (one-shot Namespace list). With none annotated yet it falls back to the agent's own namespace; when that cannot be determined the cache stays cluster-wide. Namespaces annotated later get per-namespace runtime informer factories |
| Tenant source | Namespace-level `triageagent.dev/tenant` annotation only. No workload- or pod-level annotation can set or change tenant attribution |
| Triage exclusion | `triageagent.dev/triage: "false"` on a workload, its pod template, or its Namespace removes that workload (or every workload in the namespace) from everything the agent sends: no virtual app, no Warning events, no log/RED/USE/topology entries; the `ebpf` role does not instrument it and the log-exporter does not tail an excluded namespace. A namespace-level `false` is not overridden by a workload-level value |
| Push authentication | One: the join certificate (`--join-ca-fingerprint`): Ed25519 agent key and a certificate from the core, issued on admin approval or at once for a one-time agent key (`tak_<id>_<secret>`, core ADR-090) placed in the join store as `enroll.key` by the chart (`core.agentKey`) or by `install.sh`; the agent removes the key from the store once its certificate is issued (§4 Join handshake). No HMAC handshake, token flag, token file or token chart value exists. Chart `push.*` values are read as aliases of `core.*` where `core.*` leaves a value empty (`push.join.enrollKey` as `core.agentKey`). With `--triage-endpoint` set and no `--join-ca-fingerprint` the process exits at startup, in a pod and in host mode alike; the chart requires `core.caFingerprint` with `core.host` |
| `promevents` tenant source | `NAMESPACE_TENANTS` (`ns=tenant,…`) maps an alert's `namespace` label to a tenant; `TRIAGE_TENANT`, when set, takes every other namespace and alerts with no `namespace` label. An alert with no tenant or no workload label is acknowledged and not forwarded |
| Capabilities | Synthesizes label-derived virtual apps from workload labels/annotations (`--virtual-apps=off\|on`, default `on`) carrying `triageagent.dev/domain`, `triageagent.dev/description`, `triageagent.dev/tier` and `triageagent.dev/weight` (float in [0.1, 10], strict parse, group maximum, namespace inheritance); streams virtual apps + Kubernetes Warning events to the core; collects log-derived error/warn metrics, eBPF HTTP and gRPC RED metrics, cgroup v2 / PSI USE metrics, and an observed service topology from L7 client spans and, when enabled, L4 network flows; per-key baseline-deviation gates decide which RED/USE/log windows are reported |
| Model role | None — no LLM or model invocation anywhere in any of the four modules. No model SDK in any `go.mod`; no prompts, no tool wiring, no model client. Model names in `gcpevents/catalog_gen.go` are GCP billing-catalog lookup data |
| Runtime | In-cluster controller, optional leader election; node roles run one instance per node via DaemonSet; `gcpevents` runs as two Cloud Run gen2 functions (Pub/Sub-triggered and Cloud Scheduler-driven); `promevents` runs as a single-replica Deployment that the in-repo manifest places in the core's namespace |
| Public accessibility | The chart creates no Ingress, LoadBalancer or NodePort; outbound-only toward the core when push mode is enabled. The controller serves the sensor stream and, when enabled, the OTLP receiver (§6) on a ClusterIP Service inside the cluster (`otlp.extraNames` adds host names and IP addresses to the serving certificate for senders outside the cluster); the node roles open no listener. Cloud Run: the Service Health poller is documented `--ingress-settings=internal-only --no-allow-unauthenticated`; the Pub/Sub-triggered function's documented deploy sets neither flag. `promevents` is exposed on a ClusterIP Service only |
| Data access | Reads cluster resources to synthesize virtual apps (informer cache, `managedFields` stripped); no object is written back to the cluster. Push mode sends whole virtual-app objects and whole `corev1.Event` (Warning) objects off-cluster, verbatim and unredacted, including their `message` and `annotations`. `gcpevents` reads GCP Cloud Billing anomaly notifications, Personalized Service Health and Cloud Monitoring incident notifications. `promevents` receives Alertmanager webhook bodies and forwards each alert's labels, annotations, fingerprint, start time and generator URL in the event's `raw` field |
| Component data on the wire | Component entries carry group/kind/name/status only (`ObjectStatus`); no component object body, and no Secret or ConfigMap contents, ever leave the process |
| Log data on the wire | The log-exporter role classifies container log lines and, per distinct error fingerprint, attaches a `log.sample` attribute carrying a raw, unmasked exemplar of the first matching line — leading structural noise stripped and truncated to `--log-exporter-sample-max-len` (default 160 chars), 8 distinct fingerprints per (namespace, service) by default. Masking is applied to the identity fingerprint only, not to the exported sample. The value travels to the controller on the sensor stream (§4) and is forwarded on the `log_metrics` frame (≤256 chars on the wire) |
| Log collection scope | `--log-exporter-include-namespaces` (repeatable) restricts tailing to exact namespace names. Empty (the default) resolves to the live `triageagent.dev/tenant`-annotated namespace set, tracked by a cluster-scoped Namespace informer. When that set cannot be resolved (no `get/list/watch` on namespaces), the gate denies every namespace and the role reads nothing |
| Utilization data on the wire | The `use_summary` frame carries, per (namespace, service) and taken from the worst pod by memory percentage: memory and CPU utilization against the container limit, against the node's total capacity, and against the pod spec's summed regular-container requests, plus working-set bytes, resolved limit and resolved request absolutes. Node totals are not carried; the node percentage is. No percentage is clamped on this side |
| Utilization service identity | The (namespace, service) key of each reported pod is resolved in the controller from the pod's owner chain — Pod → ReplicaSet → Deployment, or StatefulSet, DaemonSet, standalone ReplicaSet, Job → CronJob, standalone Job — through the same identity chain that names virtual Applications (`triageagent.dev/virtual-app-group` annotation, else `app.kubernetes.io/part-of` → `instance` → `name`, else the object's own name). Any failure keeps the exporter's own `service.name` attribute |
| Observed topology data | When `--topology-enabled`, service-to-service dependency edges leave the cluster. Two edge sources: L7 client spans (`calls` per window; protocol `http`/`grpc`/`db`) and, when the instrumenter has network flows enabled, L4 flows from `obi.network.flow.bytes` (`bytes` per window; protocol `tcp`). Edge endpoints are named by virtual-app identity, not by raw object name. A destination that does not resolve to an in-scope tracked workload is carried as an `External` string (≤128 chars): an IP literal, an external hostname, the instrumenter's `outgoing` placeholder for an address it could not name, or `<owner>.<namespace>` for a cluster destination outside push scope or not tracked by the identity index. A source whose owner is not a tracked workload is dropped, never emitted under its raw name. Edges are attributed to their SOURCE namespace's tenant; a cross-tenant edge's destination namespace and workload ride along on the source tenant's frames. One frame carries at most 200 nodes and 500 edges, top-ranked by calls then bytes |
| Topology destination resolution (L7) | `server.address` is resolved through cluster objects, not by parsing DNS shape: an IP literal through the ClusterIP index; a hostname as `<svc>` in the caller's namespace, then `<svc>.<ns>`, then `<svc>.<ns>.svc[.<any suffix>]`, then the Ingress host index (any Ingress rule host, uncontested; a host claimed by two different backend Services is unresolved); the resolved Service's selector is matched against tracked workloads' pod-template labels (exact label set preferred, else lexically first name), then that workload's identity is taken from the index. Any step failing yields `External`, except that, when the resolver leaves an address external (always, for an agent with no Service index), a bare `<svc>`, `<svc>.<ns>`, `<svc>.<ns>.svc[.<domain>]` that matches a service already read as a request destination in a namespace in scope is named in-cluster (`knownCallee`) |
| Topology identity dependency | The identity index is rebuilt from the virtual-app workload snapshot on every recompute and is empty with `--virtual-apps=off`; in that mode every L7 client edge whose sample carries an owner label and every L4 flow row is dropped, and the RED destination identity falls back to the instrumenter's `service.name` |
| Network-flow capture | Enabled by the chart's `ebpf.networkFlows.enabled` (rendered into the mounted OBI config) or `OBI_NETWORK_FLOWS=true` on the env-built path: `network: {enable: true, source: socket_filter, guess_ports: ordinal}`. Capture is host-interface-wide and independent of `discovery.instrument`; Kubernetes decoration comes from the instrumenter's pod-metadata informer, restricted to pods on the local node (`meta_restrict_local_node: true`, both config paths). Exported flow attributes are selected to `k8s.src/dst.owner.name`, `k8s.src/dst.namespace`, `k8s.src/dst.owner.type` and `direction` (no addresses, ports or interface names). A row becomes an edge only when both owner names are non-empty, neither owner type is `Node`, and `direction` is `request`; a connection whose initiator was not observed has its direction inferred by the ordinal rule (higher port = client). Rows sharing a (source, destination) name pair are summed, workload-typed rows preferred over `Service`-typed ones |
| PII | None handled by design. Cost anomaly payloads carry spend amounts, billing account and project identifiers (financial, not personal). Kubernetes Event messages and log-derived samples are free text whose content is determined by the workloads observed |
| Sensitivity | In-cluster control-plane component with cluster-wide read and an off-cluster egress channel. In the `ebpf` role, additionally a node-privileged eBPF workload (see §5) that, with network flows enabled, runs in the host network namespace |

| Join handshake | The agent puts a fresh 32-byte nonce in the `X-Triage-Agent-Nonce` upgrade header. A challenge without the agent-nonce echo, or with a different one, is refused. Otherwise, or with less than a third of the certificate's lifetime left, it sends a CSR (CN `agent:<cluster>`, URIs `triage:cluster/<cluster>`, `triage:tenant/<t>`) with a proof signature, plus the one-time agent key from `enroll.key` when there is no usable certificate and one is stored, and the connection ends with `issued`, `pending` (awaiting admin approval) or a refusal. An issued certificate is saved only if it parses, chains to the trusted CA, is currently valid, carries this agent's public key and names exactly the requested cluster and tenants; otherwise it is discarded and the connection ends. On `issued` for a key join the agent deletes `enroll.key` from the store and seeds the workspace namespace scope from the result's tenant bindings.
